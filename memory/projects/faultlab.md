# FaultLab project context

## Purpose

FaultLab is a crash-test lab for agents that change state through tools. It makes a synthetic service misbehave, compares the agent's original report with actual service state, reproduces an error, asks a model for a bounded recovery policy, and challenges that policy before accepting it. Learning changes a wrapper policy, not model weights.

The current environment is a manually built mock shop, not a generator for arbitrary agent environments. The task is to upgrade an authorized order to express shipping and record exactly one truthful confirmation. No real order or email is involved. A new domain needs reviewed service semantics, reset/adapter support and its own checks. A native smolagents adapter has an independently measured live baseline, but accepted-policy transfer remains unproven.

Roles: Actor performs the task; Explorer selects faults/challenges; Mechanic proposes a policy; fixed Referee checks C1–C8 against private simulator truth; coordinator enforces evidence and budgets. W&B Inference hosts models; Weave stores traces/evaluations that are read back before optimization. Aria is advisory and currently disabled.

- Phase 14: answered Phase 13's open question for **$0** - 16 agents, four angles, three adversarial lenses each, no paid run. **The failing control call is `create()` (`POST /control/worlds`)**: `execute_slots` wraps `runner.run` in no try, `runner.run` has no finally and two blanket `except Exception`, and `create()` is the only HTTP call in the unprotected window. All 14 `ReadError` studies leave exactly one slot `INTERRUPTED`; all 56 evidence-channel studies leave zero. **The request never reached the simulator** (zero of 3,730 world files carry the 14 episode_ids; zero orphans with a Phase 13 mtime; a server-side counter gave 884 of 884). **Why it fails was then FOUND in a second free round**: uvicorn arms its keep-alive timer when it finishes *writing* a response (`h11_impl.py:331`), so its deadline always precedes the client's, and its handler closes the transport without draining the socket (`:372`) - on macOS that emits RST, discarding the request before the app runs. Every observation follows: threshold at exactly 5.000s, no world file, always `ReadError` never `RemoteProtocolError`, and a hazard that *decays* rather than a band (there is no upper edge; zero above 6s has P = 0.68). **The real fix is connection lifetime**: `keepalive_expiry=2.0` client-side so the client always closes first (verified: at 4.9s idle the old client reused, the new dials fresh), plus `--timeout-keep-alive 75` server-side. The bounded `create()` retry stays as a backstop - **551 of 551** induced failures recovered on attempt 2 - after review found it had no jitter and an unclamped backoff index. Measured idempotency: non-observer `advance` double-applies (tick 2 -> 4) and must never be retried; the observer `advance` IS latched, correcting Phase 13. Also corrected: the protected teardown calls did **not** fail zero times - 3 `SIMULATOR_OR_SCORER_ERROR` episodes each killed a study via the `EvidenceDenied` route, still open. `docs/part2/PHASE14_RESULTS.md`.

## Current result

The testing and evidence pipeline is useful and operating, and it now has a measured negative result to its name: Phase 4 caught a real regression that a completion-only metric would have missed. **The promise of a useful generated repair remains unproven.** No policy has been ACCEPTED, no positive completion validation occurred, and no accepted-policy final audit or transfer occurred. A completed study means its declared process ended, not that it improved the agent.

Latest checks: 549 backend tests, 121 frontend tests, build and three browser fixtures passed on the frozen Phase 4 source. Real dashboard navigation, source reports, simulator effects, Weave and restart were inspected manually. Old records are unchanged. Do not rerun broad tests just to restate this baseline; run relevant checks after actual changes.
